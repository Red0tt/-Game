# 第二单元：有限水量、流动、冷却规则

本文件描述已经落入代码的第二单元规则。第一单元 Level01–07、Fanhua01–09及方向教学沿用原有机制。

新规则入口是玩家身上的 `PrototypeWaterLevel` 组件；没有该组件的场景不启用有限水量、水流、冷却资源消耗和翻花锁定。

## 1. 两种形态

| 对象 | 2.5D | 2D |
|---|---|---|
| 蓝块 | 有碰撞、挡路，可按现有推箱条件移动 | 隐藏实体，释放其剩余水量；来源位置显示蓝色细框 |
| 黄色 | 翻花实体障碍 | 实心平台，可挡水、承托水和人物 |
| 未冷却红格 | 实体障碍，不造成接触伤害 | 接触人物使其失败；对水是有冷却消耗的阻挡边界 |
| 完全冷却灰格 | 固定实体，无推箱能力 | 安全实体，可落脚，继续阻挡水 |
| 普通2.5D地板 | 支持走格和推箱 | 背景，不承水，不改变水的边界 |
| 2.5D洞、仅2.5D墙 | 决定走格可达性 | 不参与水流；只有明确加入2D投影的实体才挡水 |

坐标仍是原项目的X/Z；2D重力沿图面-Z方向。Unity世界Y只表示立体厚度，不参与水域面积计算。

## 2. 水量与时间

1. 每个初始蓝块携带 **1.00份水量**，一份水占一个完整2D格的面积。不会因接触黄色而乘以任意深度。
2. 一格可容纳0–1份水；不足一份时显示为格子底部相应高度的水层。
3. 连通水体允许混合。每份水仍记住来自哪个蓝块，便于计量消耗、流失和回收。
4. 总量核算：`初始水量 = 当前场内水量 + 冷却消耗 + 流失`。数值测试允许浮点误差，不能通过切换、推动或重拉制造水。
5. 仅2D形态推进水流，默认每0.06秒一个流动步。2.5D暂停水的位置、水量和冷却进度；没有背景里继续流走或灭火的情况。
6. 原型不模拟水压冲击、浪花、蒸发、无限水源、流速推人或氧气。低处连通空间会快速均衡，是解谜用的格子流体，不是连续流体物理。

## 3. 每个流动步的判定

1. 红格正上方的水尝试向下落入红格时，先参与冷却。
2. 下格无实体阻挡且有容量，优先向下转移。
3. 已被实体承托的水，先通过同高或更低的连通路径填入附近低处，不能穿墙，也不能越过高于当前水面的墙。
4. 相邻同高度格子均衡水量；边缘下方开放时，水会沿边缘继续落下。空中的下落水柱不会被当成有底水池横向铺开。
5. 本步新落到红格正上方的水继续参与冷却；左右、下方接触不计。
6. 到达地图下边界或左右开放边界的水计入流失。边界不会偷偷提供看不见的挡水墙。

流动边界只来自2D实体：场景里指定的2D平台/墙、展开的黄格和红/灰格。不同翻花之间没有“不能互相接水”的限制。普通地板、棋盘底纹和2.5D洞不输入流动求解器。

## 4. 黄色与容器

- 黄色只负责实体承托和阻挡，不吸水、不增殖水、不自动围住两侧。
- 开放平台上的水会流向开放边缘；不能用一排黄格凭空维持三格高水柱。
- 水池必须由实际2D地形构成底部和侧壁。池沿、缺口高度决定何时溢出。
- 同样水量在窄池里更深，在宽池里更浅；水少时无法到达高岸。
- 翻花保留背身拉操作，不需要拉到墙边。普通2.5D走道供拉伸与绕行，2D地形负责承水，两者可以重叠布局。

## 5. 红格冷却

- **只有蓝水从红格正上方向下落入，才能合成灰色石头。** 左右、下方和对角接触都不积累冷却，也不消耗水量。
- 横向流来的水只有先到达红格上方、再向下落到它上面，才符合合成条件；不能从红格侧面直接合成。
- **冷却一个完整红格累计消耗1.00份水量。** 水从场内扣除，并记入来源蓝块的已消耗量。
- 小于一份水只能积累冷却进度，红色会变暗；直到完全变灰之前仍然危险。
- 完成冷却后，原红格在原位置变成同尺寸灰格；两种形态都保留。
- 灰格不能推动，不会自动变回红色，能被人物踩住，也会改变后续水路。
- 一份水最多完成一个红格的冷却，不能无限传染整条火带。若一份水分散后从上方分别落到多个红格，可能都只达到部分冷却。
- 水直接落到某一火格上时先处理该接触，再横向扩散，避免一整份水在接触瞬间被拆散到相邻火格。
- 红格不下落；人物在2D中触碰未冷却红格，回到关卡起始状态。沿用现有失败与撤回约定，失败不会偷偷保留已开的门。

## 6. 切换、蓝块回收与推动

### 固定来源，不搬运人物

- 每个蓝块保留自己的放水位置，即“来源锚点”。水流到池里后，蓝块不会跟着变成池中一排新的实体。
- 2D中用蓝色细框预览这些锚点；2.5D中隐藏水，尚有剩余水量的蓝块回到自身锚点并恢复阻挡。
- 人物仍沿用切换瞬间的X/Z格，不能靠切换自动传送到岸上。
- 当前格必须有2.5D地板，且不会与恢复的蓝块、墙或其他实体重叠，才能切回。
- 无效切换只拒绝本次请求并提示原因；不持续重试，不锁住后续游泳输入，不把蓝块挤到别的格子。

### 水量不会因回收而重置

- 消耗和流失都从来源蓝块的余额扣除。完全用尽的蓝块消失；部分余额仍保留为实体蓝块，旁边显示剩余份数。
- 切回2D时，未推动的蓝块继续原先暂停的水流分布，不重复生成一份新水。
- 在2.5D推走某个蓝块后，再次进入2D时收回该来源散落的剩余水，从新位置重新释放。只搬运余额，不退还冷却或流失的水量。
- 水混合后的消耗按该接触格内各来源的比例分摊。例如两个蓝块各贡献0.5份冷却同一红格，两块都只剩0.5份。

## 7. 翻花编辑与资源防复制（仅第二单元）

**首次切入2D开始本轮水模拟后，本关翻花的长度、轴向、收拢和配色锁定。**

原因是展开/换色会重建色块。若不限制这一点，玩家就能一边留下旧水或灰格，一边无限重建全新的蓝块。当前版本采用清楚的一次布置规则：

- 进入2D前，可自由换色、收拢、重拉。
- 开始放水后，可以切换形态、推尚存蓝块、游泳和操作机关，但不能重建翻花。
- Z撤回到首次放水前，可以重新编辑翻花；R重开同样恢复初始布置阶段。
- 该限制只作用于第二单元。第一单元原先用于换轴、换色、重拉的关卡行为保持不变。

这是当前实现的资源约束。如果未来需要在同一关中反复折叠翻花，需要另写“已消耗水量随翻花保留”的重建机制，不能直接解除锁定。

## 8. 游泳、出水与开关

- 人物中心进入实际水域才进入游泳；水流走后恢复普通下落。
- 左右游动，W上浮，S下潜；无输入时缓慢上浮。
- 只有当前连通水柱的近水面、且水体确有下方承托时，Space才提供出水跳跃。高处孤立水滴不会赋予深水角色二段跳。
- 水不会把人物压死，也不作为未冷却时的实心蓝色踏台。
- 本关水底开关需要人物在水中实际接触；触发后锁定开门，不需要一直压住。
- 出口只检查人物实际到达，不检查“游泳/开关/灭火完成清单”。必要性来自地形、距离与门的阻挡。

## 9. 撤回与重置

Z一起恢复人物、视角、蓝块位置、水量来源、完整水分布、模拟时钟、冷却进度、灰格和门。

R恢复所有初始水量、红格和布置阶段。沿用现有“R也能被Z撤回”的约定。恢复后不会有一帧实体水把人物挤开的现象：水的忽略碰撞关系在首个物理步之前重新设置。
